# SAKAY 1.1.0 release checks

Release candidates: Passenger **1.1.0+21**, Driver **1.1.0+21**, Admin web **1.1.0+2**. The mobile catalog previously advertised 1.0.5+20; build 21 was available for both apps.

The 11 October 2026 checks passed: 248 backend regression/migration tests, 62 unit checks, 174 Flutter tests, 10 legacy system/API/Admin scenarios, 26 fault/expiry scenarios, 63 reliability scenarios and 42 additional browser scenarios. Another 25 automation checks passed with isolated staging configuration, and the latest Admin web build passed its two browser rechecks. All four Flutter projects have clean analysis. Android release package IDs, version/build, universal architectures and signatures matching existing installations were verified.

The reliability run completed 30 terminal group and 30 roadside solo journeys, last-seat contention, listener/database-client recovery and a five-minute diagnostic at 5, 10, 25 and 50 authenticated users. The fleet review rendered 100 jeepneys, exercised search/filtering and observed accepted driver location changes without reload. Browser evidence covers actual booking controls, changed fares, cancellation, reload, individual totals, member drop-offs, narrow screens, glass notices, swipe/timeout, map zoom and Waiting/Cancel.

The release also fixes malformed Passenger GPS, concurrent para cooldown bypass, misleading errors after committed notifications/support messages, orphan support threads, lost unread increments, Driver general-help restrictions, unsafe capacity reductions, inactive booking assignments, live route path edits and booking TTL deletion. `scripts/migrate-pickup-retention.cjs` replaces only the booking expiry TTL index with a normal index, preserving history and all other indexes. Run this migration before deploying the matching schema. Expiry ends reservations without deleting their records; previously deleted records are not recovered.

Publish the verified APKs through the existing mobile release publisher after successful deployment. Preserve the existing required-update minimum. GitHub `main` deploys the backend through the existing AWS workflow and the administrator web through the existing deployment integration. Admin builds emit a public `release.json` containing only app/version/build/commit metadata.

Automatic group booking and Driver lifecycle activation remain disabled in production pending physical-phone acceptance. Existing journeys retain their behavior. Browser testing uses temporary loopback MongoDB/Redis and controlled GPS, email transport and fault injection. It does not certify Android background GPS, installation/update, battery restrictions, physical boarding/unloading, external SMTP/FCM/social login, multi-hour soak, OS recovery or 100 simultaneous production GPS transmitters.

Full logs, screenshots, load measurements, APK checksums and publication proof are generated locally at `artifacts/full_system_release_2026-10-11/index.html` and `REPORT.md`. Run `node tools/write-full-system-release-report.cjs` to regenerate the report from the recorded evidence; it refuses a passing gate when required final evidence is missing or fails. Initial failures are retained separately, including corrected fixtures and build output-path errors.
